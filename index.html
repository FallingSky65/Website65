PathTracerFS65

  • Source code: https://github.com/FallingSky65/PathTracerFS65
  • Stack: C++/SDL2

This is a path tracer program I wrote in 2023, before I began to use GitHub regularly. The original code is unchanged from when I last updated it on September 4, 2023.

This program renders a simple scene by simulating photon interactions with surfaces, with each intersection reflecting and accumulating colored light. The code is run entirely on a single CPU thread and the program stores the results for 1/10/50/100 photons per pixel, and displays the final result in a new window.

Fluid65

  • Source code: https://github.com/FallingSky65/Fluid65
  • Try the web demo in your browser!
  • Stack: C++/raylib/GLSL

In total, I've built five fluid simulation projects, each focused on learning and implementing new techniques for faster and more optimized fluid modeling.

This was my first fluid simulation, inspired by this YouTube video by Sebastian Lague. It uses smoothed particle hydrodynamics (SPH) (Müller 2003) to simulate fluid physics for 512 particles at 60 FPS. It runs on a single CPU thread in C++, and graphics were done using raylib and GLSL shaders.

FluidSim65

  • Source code: https://github.com/FallingSky65/FluidSim65
  • Stack: C/raylib/GLSL

This was my second fluid simulation, and it improved on the first in three main ways:

  1. I used spatial hashing to separate the space into discrete cells for optimized particle-particle lookup, going from O(N^2) to O(N).
  2. I parallelized the computation across multiple CPU threads.
  3. I implemented screen-space rendering inspired by this YouTube video.

This simulation could handle 20x more particles than my first, simulating physics for 10,000 particles at 60 FPS.

metaleulerianfluid

  • Source code: https://github.com/FallingSky65/metaleulerianfluid
  • Stack: C++/SDL3/MSL

This is my third fluid simulation. Unlike the previous two, which were particle-based (Lagrangian) and ran on the CPU, this was grid-based (Eulerian) and ran on the GPU using Metal compute shaders. Seeing the performance boost from the multithreaded parallel processing in my second iteration, this version was focused on learning GPU programming so I could harness the GPU chip for more powerful parallel compute.

LiquidMetal65

  • Source code: https://github.com/FallingSky65/LiquidMetal65
  • Stack: C/SDL3/MSL

This is my fourth fluid simulation. Using the GPU programming I learned from my third iteration, this version reimplements the 3D SPH Lagrangian model but with the simulation GPU-accelerated by Metal compute shaders. I implemented a GPU parallel bitonic sort to facilitate this change in architecture (CPU sorts are not optimal on a GPU). This pushed my performance to 32k particles at 60 FPS.

rustyfluid65

  • Source code: https://github.com/FallingSky65/rustyfluid65
  • Stack: Rust/wgpu/WGSL

This is my fifth and most recent fluid simulation. Using the Metal graphics API locks my code to Apple's ecosystem of hardware and software, so for better cross-platform compatibility I switched to a WebGPU backend. This version boasts a hybrid bitonic sort to take advantage of local workgroup memory to reduce VRAM bandwidth bottlenecking, as well as improved physics and surface tension modeling. It can handle 100,000 particles at 60 FPS, nearly 200 times that of my first simulation.
